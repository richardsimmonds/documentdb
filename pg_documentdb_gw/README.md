# pg_documentdb_gw

`pg_documentdb_gw` is the **MongoDB wire-protocol gateway** for DocumentDB. It is a
Rust workspace that translates incoming MongoDB client connections into PostgreSQL queries
executed against the `pg_documentdb` extension.

## What it does

- Listens on a TCP port (default `10260`) and speaks the MongoDB wire protocol, so any
  MongoDB-compatible driver connects without modification.
- Parses MongoDB OP_MSG / OP_QUERY frames, dispatches them to command handlers, and
  translates each command into one or more SQL calls against `pg_documentdb`.
- Manages a pool of PostgreSQL connections via `deadpool-postgres`.
- Handles authentication (SCRAM-SHA-256), TLS termination, and session lifecycle.
- Emits OpenTelemetry metrics and traces for observability.
- Ships integration tests in `documentdb_tests` that run against a live DocumentDB stack.

## Building

### Prerequisites

- Rust (edition 2021, stable — see `rust-toolchain.toml` in the repo root)
- OpenSSL development headers
- A running PostgreSQL instance with `pg_documentdb` installed

Install Rust via [rustup](https://rustup.rs/) if needed:

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
```

### Compile

From the repo root:

```bash
make install-pg_documentdb_gw
```

Or build the gateway binary directly:

```bash
cd pg_documentdb_gw
cargo build --release -p documentdb_gateway
```

The binary is produced at `target/release/documentdb_gateway`.

See the [build-from-source guide](../docs/build-from-source.md) for full prerequisites.

## Running the standalone gateway

The standalone binary is intended for deployments where the gateway runs as a separate
process (e.g. a sidecar container) rather than as a PostgreSQL background worker.

The binary takes the path to a configuration file as its first positional argument.
If omitted, it falls back to the `SetupConfiguration.json` shipped alongside the crate.

```bash
./documentdb_gateway SetupConfiguration.json
```

Key configuration fields in `SetupConfiguration.json`:

| Field                              | Description                                                       |
|------------------------------------|-------------------------------------------------------------------|
| `NodeHostName`                     | Hostname the gateway advertises / binds to (default `localhost`)  |
| `GatewayListenPort`                | TCP port the gateway accepts MongoDB connections on (default `10260`) |
| `PostgresPort`                     | Port of the backend PostgreSQL instance the gateway connects to (default `9712`) |
| `BlockedRolePrefixes`              | Role-name prefixes that clients are not allowed to authenticate as |
| `CertificateOptions`               | TLS certificate settings (e.g. `CertType: "PemAutoGenerated"`)    |
| `HostConfigurationWatchIntervalMs` | Poll interval for hot-reloading host configuration (default `1000`) |
| `UseLocalHost`                     | Whether to bind to localhost only                                 |

See `SetupConfiguration.json` for the full schema with defaults.

## Running tests

Integration tests require a live DocumentDB stack. See
[documentdb_tests/](documentdb_tests/) for setup instructions, then:

```bash
cd pg_documentdb_gw
cargo test -p documentdb_tests
```

## Relationship to pg_documentdb_gw_host

`pg_documentdb_gw_host` is a thin PostgreSQL extension (built with
[pgrx](https://github.com/pgcentralfoundation/pgrx)) that embeds the gateway as a
**PostgreSQL background worker**. It links against `documentdb_gateway_core` (this
workspace) and runs the gateway in-process with PostgreSQL, eliminating the need for
a separate daemon. Use `pg_documentdb_gw_host` for single-node deployments; use the
standalone `documentdb_gateway` binary when you need the gateway to run independently.
